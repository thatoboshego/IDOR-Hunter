⚓ IDOR Hunter

Insecure Direct Object Reference Security Lab

A controlled, local-only penetration testing environment for learning and verifying Broken Access Control (OWASP A01:2021 · API1:2023). Authenticate as User A, User B, or the Administrator, then exploit, detect, and remediate a real IDOR vulnerability against seeded synthetic data.

  • Switchable vulnerable / secure lab modes
  • Repeatable Java-based penetration test suite
  • Live incident detection & administrator phone alerts
  • Before/after remediation evidence & guidance

⚠ For authorised educational use only, against this local lab's own synthetic data. Never target systems you do not own or have explicit permission to test.

Current Lab Mode: SECURE

What each test demonstrates

  • Own resource access — User A successfully reads a document they own.
  • Unauthorised cross-user access (IDOR) — User A requests User B's private document by changing the id. In vulnerable mode this succeeds and leaks data; in secure mode the server rejects it.
  • Nonexistent resource — requesting an id that doesn't exist returns 404, not a data leak.
  • Unauthenticated request — no session cookie at all must be rejected with 401.

Configured via environment variables (see .env.example). By default a mock telephony provider is used and no real calls are ever placed. Retry schedule: up to 3 consecutive call attempts, 10 seconds apart, bounded by 6 scheduled intervals per alert cycle.
